# v0.3.7 — list of changes

Raw list for the changelog. Nothing here is written for a release page yet.

Everything in this file is in `main` between `v0.3.6` and `9ba92a3`.

---

## Added — the application

### Corner detection and lap decomposition
- Corners are found in the lap's own trace: a stretch where lateral load stays
  above a threshold long enough to be a corner rather than a kink. No track data
  needed, so it works on mods and on tracks nobody has written a table for.
- Hysteresis on entry and exit, so a corner does not end because one sample
  dipped; a brief unload over a crest stays one corner.
- A direction change is never merged — left-then-right is two corners however
  close together.
- Per corner: direction, entry, apex (taken at the slowest point), exit, entry /
  minimum / exit speed, peak lateral g, braking point, throttle point and the
  delay from apex to throttle.
- Braking point is looked for on the straight *before* the corner, and takes the
  last braking application before the apex rather than the first.
- `decompose` charges each corner the track from its own entry to the next
  corner's entry, so a bad exit is paid for by the corner that led onto it and
  the sections sum to the lap's own delta.
- Corners are matched between laps **by distance, never by index**, with the
  directions required to agree. A corner the reference lap does not have is "no
  comparison", not a delta of zero.
- New `CORNERS` sub-tab on Analysis: per-corner table with speed deltas, plus
  the worst corner pulled apart (braking in metres, entry/minimum/exit speed,
  throttle timing).
- New key (`F` by default) hides every corner that cost less than 0.10 s.
- `LapData` carries `track_length_m`, so braking can be reported in metres; laps
  saved before this say "not measured" rather than inventing a number.

### Confidence
- `core/src/confidence.rs`: `Confidence` (Low / Medium / High) derived from a
  count of corroborating observations and their spread, not a number chosen when
  the rule was written.
- One observation is never confident, however extreme. Two agreeing are a
  coincidence.
- Observations that cancel out are Low, not "balanced".
- `Evidence::averaged_over` — an observation that is itself the mean of many
  samples counts for more than a single reading.
- Confidence markers shown beside every line of advice in the terminal.

### Car versus driver
- `core/src/driver_vs_car.rs`: over a stint, separates a symptom that ignores
  the driving from one that follows it.
- **Refuses to answer below four laps** and says so, rather than guessing.
- Verdicts: the car / the driving / could be either, each with its reasoning
  printed.
- Symptoms covered: understeer, oversteer, lockups, over-rotation.
- A noise floor, so the ordinary business of driving near the limit is not a
  symptom.
- Shown on the Engineer tab's POST-STINT column.

### Cause and check
- `Chain { cause, effect, confirm, evidence }` on `Recommendation` — why it is
  happening, and what to look at next run to know whether the change worked.
- Filled in by the camber rule so far; the other rules carry the old score and
  fall back to it.

### Receiving another machine's telemetry
- `core/src/broadcast/receiver.rs`: the other end of the UDP feed. Viewer sets
  `overlay.receive_from`, driver sets `overlay.broadcast_to`.
- What crosses is the finished frame, so the viewer sees exactly what the
  driver's engineer is saying.
- Measurements travel; preferences do not — which blocks to draw and which
  language stay the viewer's.
- New `flags::REMOTE` bit (costs no frame version) so a panel can say these are
  not your numbers.
- A datagram from an unrelated program on the same port is told apart without a
  full JSON parse.
- A sender on a different schema is refused rather than half-read.
- The socket is drained to the newest frame; a datagram that overtook a newer
  one is dropped.
- One network only. No NAT traversal, no relay, no discovery.

## Fixed — the application

- **A missing shared-memory mapping silenced the UDP feed as well.**
  `publish_overlay_frame` returned early when the overlay writer was absent, and
  the broadcast call sat after that return — so every sink lost its frames
  because the *panel's* mapping could not be opened.
- **The stint verdicts counted laps loaded from files.** A ghost from another
  day in another car was being used as corroboration for a verdict about this
  car.
- **Confidence markers rendered as an identical dash.** 🟢🟡🔴 are recent enough
  that the terminal font draws all three the same; filled / half / hollow
  circles carry it without needing colour.
- **The POST-STINT column had never been captured by `tui_tester`**, so it went
  out unreviewed release after release. It has a screenshot now.
- **The screenshot mock filled `distance` with metres** where AC publishes a
  normalised 0..1. Every consumer read it as three thousand laps — the delta
  graph resampled to a ceiling of 1.0 and drew a single sample.
- **`broadcast_name` was documented as falling back to the player name from the
  game.** It does not: the sink is built at startup, before any session.

## Removed — the application

- **Attributing an effect to a setup change.** Written, tested, and cut before
  release. It rests on identifying the loaded setup, and AC publishes only fuel,
  brake bias, pressures and camber — two setups differing solely in a roll bar
  are indistinguishable, which is exactly the change it existed to measure.
  Worse, fuel burning off mid-stint can make a different saved setup start
  matching and invent a change that never happened.

## Notes / not done

- Corner detection has not been validated against a real recorded lap. Every
  threshold is chosen against synthetic traces.
- `Chain` is filled in by one rule of about twenty-one.
- Item 8 of `docs/plan-0.3.7-analysis.md` (remote reference laps) is not built —
  the plan says to prove the shape locally first, which is what the corner
  comparison does.
- No second simulator. ACC would need its own structs; its overlay is not
  possible at all, since CSP is an AC mod and ACC is Unreal Engine 4.

## Website and infrastructure

Separate from the application release — cut this section if it does not belong
in the changelog.

- New landing page at **https://proengineer.app**, in the application's own
  colour theme. Source in `site/`.
- Second copy at `rgosh.github.io/ac-pro-engineer`; neither redirects to the
  other, both declare `canonical` on the domain.
- Domain served from its own host with nginx and a Let's Encrypt certificate;
  `site/deploy.sh` uploads it (untracked, it names host paths).
- `.github/workflows/pages.yml` deploys the GitHub copy and fails the build on:
  a referenced picture or icon that does not exist, an unsubstituted sitemap
  date, a tab strip whose order is not the page's order, and any advertised
  feature count that disagrees with the number of rows written.
- SEO: `robots.txt`, `sitemap.xml` dated from the deploying commit, self-
  referential canonical, `og:image` card, `max-image-preview:large`, and three
  structured-data blocks (`SoftwareApplication`, `FAQPage`, `WebSite`).
- Icon set drawn to match the site: `favicon.ico` (16/32/48, BMP inside),
  `icon.svg`, 16/32/192/512 PNGs, apple-touch icon, web manifest. Also shown on
  the page itself, in the window title bar and the footer.
- All 115 features written out in twelve folding sections, plus a comparison
  against named tools (Track Titan, Delta, RaceLab, SimHub, Crew Chief,
  MoTeC i2) checked in August 2026, with unknown cells left as "not stated" and
  a table of what the program deliberately does not do.
- Two download routes: OverTake for a normal download page, GitHub for the same
  builds plus the source and the Proton bridge.
- Presentation: sticky tab strip with a scroll-progress bar, block logo that
  draws itself, headings that type as they are scrolled to, sample output that
  prints line by line, staggered cards, section-arrival marking, CRT sweep,
  phosphor glow. All opacity/transform only and all off under
  `prefers-reduced-motion`.
- One script on the page: a ~40-line IntersectionObserver scrollspy. Everything
  else is CSS.
- Mobile: stacked tables, horizontally scrolling comparison table and tab strip,
  full-width buttons and a two-column stat grid under 400 px.

### Server-side fixes made while doing this
- Freed 6 GB on the host (pip cache, `btmp`, journal, apt) — 95 % to 67 % full.
- `types { … }` in an nginx server block **replaces** the whole MIME table
  rather than adding to it; it stripped `text/html` and the page downloaded
  instead of rendering. Replaced with a single `location`.
- The page went out with no cache headers: the rule was on `location = /`, and
  `index index.html` internally redirects to `/index.html`, which re-matches
  `location /`. Now `no-cache` (revalidate) for HTML, 30 days for images.

### Outstanding
- The server still allows SSH password authentication as root on port 22 with no
  fail2ban; `btmp` held 2.76 million failed attempts before it was truncated.
- The site is not in Google Search Console and `sitemap.xml` has not been
  submitted.
