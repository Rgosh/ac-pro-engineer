A race engineer that reads your telemetry and tells you what to change.

Free and open source. Reads the simulator's shared memory directly, analyses tyre temperatures and pressures, brake heat, fuel and how you are driving, and says something useful about it — in a fast terminal on your second screen and in the game itself. Assetto Corsa today, built so another simulator is a folder rather than a rewrite.

$ ./pro_engineer

Download Install guide GitHub

Windows · Linux · Steam Deck under Proton. About 0.1 % of one CPU core.

WHAT IT DOES

Not a graph viewer. It reads the numbers and says what they mean.

▸ Tyres, properly

Pressure and inner/middle/outer temperature per corner, the distance from your target hot pressure, and a cold-pressure calculator that says what to set in the garage to arrive there once they are up to temperature.

▸ Advice that groups itself

Four cold tyres is one sentence, not four. Ranked by severity, and it says how sure it is — a verdict from one odd frame does not get the same voice as one from four consistent corners.

▸ A debrief after the lap

What the engineer made of the lap you just finished: pressures and temperatures against your windows, camber per axle, brakes, and how it was driven. Page back through the last three.

▸ Fuel and stints

Consumption measured from your own laps, laps remaining, what you need to finish and how short you are. Tyre life in the worst corner, and which runs out first.

▸ A real ghost

Delta against your own recorded best lap rather than whatever reference the game picked, with sector splits and MoTeC-compatible CSV export.

▸ Nothing in the game

The desktop side computes; the in-game panel draws. Lua runs on the render thread, where a millisecond is a sixth of the frame budget — so nothing that can be done outside the game is done inside it.

IN THE GAME

A Custom Shaders Patch app. It installs itself every time the application starts, so updating one updates the other. Every block can be switched off.

Five windows you can open and close independently: the main panel, the engineer, telemetry, status, and the lap debrief. Each block inside them switches off on its own, and the choice survives closing the window.

  • Main panel — speed, gear, four corners, the engineer
  • Telemetry — pressures, temperatures and brakes in full
  • Lap debrief — what the engineer made of the last lap
  • Engineer — the advice on its own, for a corner of the screen
  • Status — versions, the link to the application, what is connected
  • Settings — every block, in the game
  • Waiting — what it says before the application is up

Screenshots rather than inline pictures: the panel is a few hundred pixels across on a windscreen, which is the whole point of it — and at that size it neither fills a column here nor survives being stretched to fit one.

ON THE SECOND SCREEN

Nine tabs, every keyboard shortcut rebindable, and every on-screen hint printed from the binding — so it cannot tell you the wrong key.

WHERE THE TIME WENT

Corners are found in the trace — a stretch where lateral load stays up long enough to be a corner rather than a kink — so it needs no track data and works on mods.

It will not invent a comparison. A corner the reference lap does not have is drawn as no comparison rather than as a delta of zero, and braking in metres needs the track's length rather than a guess at it.

WATCHING SOMEONE ELSE DRIVE

A driver is on track and cannot look away. A friend on the same network runs the same program, sets it to receive, and sees their telemetry and their engineer's advice. 

# the driver
"overlay": { "broadcast_to": "192.168.1.42:9001" }

# the friend watching
"overlay": { "receive_from": "0.0.0.0:9001" }

One network, and that is all. Two houses behind two routers is NAT, which needs a forwarded port or a relay in the middle — not built. There is no discovery and no championship mode: you type an address. It is off unless you set one, because this is telemetry about a person.

The same feed is plain JSON over UDP, ten times a second, so writing your own front end is about fifteen lines of Python.

EVERY FEATURE

All of it, written out. If you are deciding whether this replaces something you already use, this is the list to read.

Tyres and brakes

Tyre pressure per cornerLive, in psi, bar or kPa.
Inner / middle / outer temperatureAll three per corner, not just the middle. The spread is what says whether a tyre is leaning the right way, which is the reading camber advice is made of.
Distance from your target hot pressurePer corner, with front and rear targets set separately.
Cold pressure calculatorWhat to set in the garage to arrive at your hot target, from the ambient and track temperature.
Brake temperaturePer corner, with a configurable ceiling, and an overheating verdict on the lap summary.
Tyre wearPer corner, as a percentage of the tread.
Remaining tyre lifeIn laps, taken from the worst corner rather than the average — a set is finished when one corner is.
Camber advicePer axle, from the inner-minus-outer spread, keeping the sign. An outer edge running hot wants more negative camber, and reading only the magnitude gives exactly the opposite advice.
Stint lengthHow long you have been on this set, which is not the lap count.

The race engineer

Plain-language adviceSentences, not thresholds. "Fronts over 28.4 psi (target 27.5)" with what to do about it.
Grouped findingsFour cold tyres is one line, not four. Fronts, rears, left side, right side, all four.
Severity rankingInfo, warning, critical, worst first, so the line you read at 200 km/h is the one that matters.
Up to eight linesWith a slider for how many reach the overlay, and the number the application actually sent printed under it.
Confidence on every lineA count of corroborating observations and their spread — not a number picked while writing the rule. One observation is never confident however extreme it is.
New advice looks differentFrom advice that has been on screen for four laps.
Cause and checkWhere a rule can state one: why it is happening, and what to look at next run to know whether the change worked.

After the lap

Lap debriefPressures and temperatures against your own windows, camber per axle, brakes, and how the lap was driven — up to eight lines.
Three laps of historyPage back through them with the game paused. In the terminal and in the game.
Sector times against the session's bestFour tenths spread across a lap is a shrug; four tenths in one sector is a corner to go and look at.
Compare with the previous lap or your bestBoth, because they answer different questions.
What is leftLaps of tyre life and laps of fuel, coloured by whichever runs out first.
A clean lap says soRather than leaving an empty column that reads as "the analysis did not run".

Lap and corner analysis

Corner detection from the traceA stretch where lateral load stays up long enough to be a corner. No track data, so it works on mods and on tracks nobody has written a table for.
Corner-by-corner decompositionWhere the time went, with the sections adding up to the lap's own delta.
Only the losses that matterOne key hides every corner that cost less than a tenth.
Braking point in metresHow much later or earlier than the reference, on the straight before the corner.
Entry, minimum and exit speedAll three against the reference, per corner.
Throttle timingHow long after the apex you got back on the power, against the reference.
Ghost delta by distanceAgainst your own recorded best lap, not whatever reference the game picked.
TracesSpeed, both pedals, steering, delta, slip and RPM against time and distance.
Damper histogramsSuspension travel distribution per corner.
Save and load lapsAs JSON with full metadata, and load one back as a ghost on another day.
MoTeC-compatible CSV exportNamed after the car, track and lap.

The car or the driving

Stint-level attributionUndersteer that turns up in the same quantity on every lap while the lap times move about is not following the driving. One that comes and goes is.
It refuses to answer earlyBelow four laps it says so rather than guessing. One lap genuinely cannot tell a car that understeers from a driver who turns in too early — they produce the same trace.
Driving style, countedSmoothness, aggression, trail braking, coasting, pedal overlap, full throttle percentage and grip usage.
Incidents, countedLockups, wheelspin, understeer and oversteer moments, and over-rotation where the tyres are scrubbing.

Fuel and strategy

Consumption from your own lapsMeasured, not taken from the car's data files.
Laps remaining on what is in the tankWith a configurable safety margin and a low-fuel warning.
Fuel needed to finishAnd how short you are, for a race of a given length.
Race pace historyLap times across the stint, so you can see the drop-off rather than feel it.

Force feedback

Clipping meterWhether the wheel is saturating and losing every detail above the clip point — the most common reason a car "feels numb".

Setups

Setup browserCommunity setups by car and track, installed into the game without restarting it.
Setup comparisonField-by-field difference between two setups.
Cold pressure targets per setupRead from the setup file rather than assumed.

What it deliberately does not do

Cross the internetSharing works on one network. Two houses behind two routers needs a relay, which is not built.
Read a setup you did not saveThe simulator does not publish the loaded setup, so it cannot be attributed to a change reliably. Better to say nothing than to guess.
Support another simulator yetThe architecture is a folder per game and the boundary is real. Nobody has written the second folder.
Overlay outside Custom Shaders PatchThere was a second, desktop-drawn overlay. It did not survive exclusive fullscreen, never appeared in VR, and was invisible to the game's own screenshots. It was removed rather than half-fixed.

INSTALL

Windows

Download, unzip, run. It finds Assetto Corsa, writes the in-game panel, and creates the shared memory the panel reads. Nothing to start in a particular order. 

# unzip anywhere, then
ac_pro_engineer.exe

Linux & Steam Deck

The desktop side works on its own. The overlay needs a small bridge running inside the game's Proton prefix, because only a Windows process in there can give the shared memory the name the game is allowed to open. 

./pro_engineer

# for the in-game overlay, leave this running too
protontricks-launch --appid 244210 shm-bridge.exe

From source

git clone https://github.com/Rgosh/ac-pro-engineer.git
cd ac-pro-engineer
cargo run --release

QUESTIONS

Is it free?

Yes, and open source under the MIT licence. No account, no subscription, no telemetry collected about you.

Does it work on Linux or a Steam Deck?

Yes. The desktop side is native. The in-game overlay additionally needs a small bridge running inside the game's Proton prefix, because only a Windows process in there can give the shared memory the name the game is allowed to open. The application ships the bridge and can fetch a matching one for you.

Will it cost me frames?

The desktop side is a terminal application at about 0.1 % of one core with no GPU cost. The in-game panel draws and nothing else — every calculation happens outside the game, because Lua runs on the render thread where a millisecond is a sixth of the frame budget at 165 Hz.

Which simulators are supported?

Assetto Corsa today. The core reads a game through a boundary designed for more than one — a simulator is a folder rather than conditionals through the middle of the engineer — but no second folder is written, and we would rather say that than imply otherwise.

Do I need Custom Shaders Patch?

Only for the in-game overlay. Everything else — the dashboard, the analysis, the engineer, the strategy work — runs without it.

Can I use my own reference lap?

Yes. Laps are saved as JSON with full metadata and can be loaded back as a ghost on another day, and the corner analysis compares against whichever lap you choose.

Can a friend see my telemetry?

On the same network, yes — they set an address to listen on and see your numbers and your engineer's advice in their own panel. It is off unless you turn it on, because it is telemetry about a person.

Does it modify my game?

It writes one folder — its own overlay app — into the game's Lua app directory, and nothing else. It reads the game's shared memory, which is the interface the game publishes for exactly this.
