A race engineer that reads your telemetry and tells you what to change.

Free and open source. Reads the simulator's shared memory directly, analyses tyre temperatures and pressures, brake heat, fuel and how you are driving, and says something useful about it — in a fast terminal on your second screen and in the game itself. Assetto Corsa today, built so another simulator is a folder rather than a rewrite.

$ ./pro_engineer

Download Install guide GitHub

Windows · Linux · Steam Deck under Proton. About 0.1 % of one CPU core.

WHAT IT DOES

Not a graph viewer. It reads the numbers and says what they mean.

▸ Tyres, properly

Pressure and inner/middle/outer temperature per corner, the distance from your target hot pressure, and a cold-pressure calculator that says what to set in the garage to arrive there once they are up to temperature.

▸ Advice that groups itself

Four cold tyres is one sentence, not four. Ranked by severity, and it says how sure it is — a verdict from one odd frame does not get the same voice as one from four consistent corners.

▸ A debrief after the lap

What the engineer made of the lap you just finished: pressures and temperatures against your windows, camber per axle, brakes, and how it was driven. Page back through the last three.

▸ Fuel and stints

Consumption measured from your own laps, laps remaining, what you need to finish and how short you are. Tyre life in the worst corner, and which runs out first.

▸ A real ghost

Delta against your own recorded best lap rather than whatever reference the game picked, with sector splits and MoTeC-compatible CSV export.

▸ Nothing in the game

The desktop side computes; the in-game panel draws. Lua runs on the render thread, where a millisecond is a sixth of the frame budget — so nothing that can be done outside the game is done inside it.

IN THE GAME

A Custom Shaders Patch app. It installs itself every time the application starts, so updating one updates the other. Every block can be switched off.

ON THE SECOND SCREEN

Nine tabs, every keyboard shortcut rebindable, and every on-screen hint printed from the binding — so it cannot tell you the wrong key.

WHERE THE TIME WENT

Corners are found in the trace — a stretch where lateral load stays up long enough to be a corner rather than a kink — so it needs no track data and works on mods.

It will not invent a comparison. A corner the reference lap does not have is drawn as no comparison rather than as a delta of zero, and braking in metres needs the track's length rather than a guess at it.

WATCHING SOMEONE ELSE DRIVE

A driver is on track and cannot look away. A friend on the same network runs the same program, sets it to receive, and sees their telemetry and their engineer's advice. 

# the driver
"overlay": { "broadcast_to": "192.168.1.42:9001" }

# the friend watching
"overlay": { "receive_from": "0.0.0.0:9001" }

One network, and that is all. Two houses behind two routers is NAT, which needs a forwarded port or a relay in the middle — not built. There is no discovery and no championship mode: you type an address. It is off unless you set one, because this is telemetry about a person.

The same feed is plain JSON over UDP, ten times a second, so writing your own front end is about fifteen lines of Python.

INSTALL

Windows

Download, unzip, run. It finds Assetto Corsa, writes the in-game panel, and creates the shared memory the panel reads. Nothing to start in a particular order. 

# unzip anywhere, then
ac_pro_engineer.exe

Linux & Steam Deck

The desktop side works on its own. The overlay needs a small bridge running inside the game's Proton prefix, because only a Windows process in there can give the shared memory the name the game is allowed to open. 

./pro_engineer

# for the in-game overlay, leave this running too
protontricks-launch --appid 244210 shm-bridge.exe

From source

git clone https://github.com/Rgosh/ac-pro-engineer.git
cd ac-pro-engineer
cargo run --release
